### 3.2 最小化准备步骤

```bash
# 1) 安装依赖（含两个测试专用 dev 依赖）
cd /d/book_tool/novel_reader
flutter pub get

# 2) 运行测试（注意：必须清除代理变量）
env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY \
    -u all_proxy -u ALL_PROXY flutter test
```

**两个环境注意事项（实测结论，非猜测）：**

1. **代理变量**：沙箱/部分环境设置了 `HTTP_PROXY` 等变量，Dart 的 WebSocket 连接会被代理劫持，导致 `flutter test` 整体挂起（表现为用例"did not complete"）。清除代理变量后恢复。
2. **flutter_test 的 MockHttpClient**：`TestWidgetsFlutterBinding` 会全局安装一个所有请求一律返回 400 的 Mock HttpClient（防止测试发真实网络请求的设计）。URL 导入等需要真实本地 HTTP 的测试，在基座 `test/functional/test_support.dart` 中通过 `HttpOverrides.global = null` 恢复真实客户端。新增 HTTP 相关测试时需保留该处理。
3. **FakeAsync 模型**：`testWidgets` 的 body 运行在 FakeAsync 作用域内，真实异步 I/O（sqflite / 文件）在 body 内直接 `await` **永远不会完成**，必须经 `tester.runAsync` 在真实异步区执行；页面自身 post-frame 回调（书架 load / 阅读器 repaginate / 设置持久化）也要在测试结束前排空，否则 tearDown 关闭数据库后回调才落地，会触发「使用已 dispose 的控制器」/「写已关闭的数据库」的 post-test 异常。基座中的 `drainRealAsync()` 即为此设计。

## 5. 缺陷列表（含回归验证轮状态）

> 严重程度定义：P1 致命（主流程不可用）/ P2 严重（用户可见的功能错误）/ P3 一般（特定场景错误或不一致）/ P4 建议（健壮性/体验优化）。

### DEF-01（P2）md 导入的书名残留 `# ` 前缀 —— ✅ 已修复

- **现象**：导入 md 文件后，书名取首行原样，`# 测试书2-山海食肆` 显示为「# 测试书2-山海食肆」（含 `# `）。
- **复现步骤**：导入 `test_books/测试书2-山海食肆.md`（首行为 `# 测试书2-山海食肆`）→ 查 `book.title`。
- **代码位置**：`lib/core/parsers/book_parser.dart:26` `guessTitle()` 直接返回首个非空行；`markdown_parser.dart` 正文侧已知 `# 标题`行并做了剥离，但书名侧未剥离。
- **影响范围**：所有 md 导入用户；书架封面/书名、阅读器章节目录均显示异常书名。
- **修复方案（已验证）**：`MarkdownParser` 对 `guessTitle` 结果增加 `_stripHeadingPrefix()`（剥离 `#{1,6}\s+`），且书名改为剥离后的纯文本后传给 `_skipTitleHeading`——顺带修复了「书名行残留在正文第一章」的次生问题（原实现下两者永远匹配不上）。
- **核验方式**：FT-IMPORT-02 断言转为 `expect(book.title, '测试书2-山海食肆')`；新增 4 个 markdown 用例覆盖多级标题剥离与正文去重，全绿。

### DEF-02（P3）纯 ASCII 二进制文件被当作正文导入 —— ✅ 已修复

- **现象**：文件字节全部 < 0x80（纯 ASCII）但内容为二进制/控制字符时，编码防护不触发，文件被当正文导入，生成乱码书籍。
- **复现步骤**：构造仅含 ASCII 控制字符的文件 → 导入 → 得到一本书（应为拒绝）。
- **代码位置**：`lib/core/text/book_text_reader.dart`，原编码防护仅覆盖「非 ASCII 且解码失败」分支。
- **影响范围**：误导入错误文件（如把可执行文件/日志当选书源）；书架出现乱码条目。
- **修复方案（已验证）**：解码成功后统一过 `_checkText()`——控制字符（`\t\n\r` 除外）与 `0x7F` 占比超过 5% 即抛中文 ImportException「文件内容异常，疑似二进制文件」。合法文本该占比≈0，无误判风险（边界样例书回归通过）。
- **核验方式**：FT-IMPORT-07 转为正向断言（抛 ImportException 且 books 表零残留），全绿。

### DEF-03（P3）书签合并完全忽略对端修改 —— ✅ 已修复

- **现象**：本地已存在同 id 书签时，对端版本被无条件跳过，无冲突解决、无提示。
- **复现步骤**：本地插入 id=bm-shared 书签（comment 为空）→ 对端推同 id 不同 comment 的书签 → 合并后本地 comment 仍为空。
- **代码位置**：`lib/services/sync/sync_service.dart` 合并循环；根因是 `Bookmark` 模型无 `updated_at` 字段。
- **影响范围**：多设备用户的书签内容无法同步更新（如对端补了批注）。
- **修复方案（已验证）**：`Bookmark` 增加 `updated_at` 字段；数据库 v1→v2 迁移（`ALTER TABLE bookmarks ADD COLUMN updated_at INTEGER NOT NULL DEFAULT 0`，SQLite 允许带默认值的 NOT NULL ADD COLUMN，旧行默认 0）；合并逻辑改为与笔记一致的 `local == null || remote.updatedAt > local.updatedAt`；`toggleBookmark` 新增时写入 `updatedAt = now`。
- **核验方式**：FT-SYNC-04 转为正向断言；新增迁移测试（旧书签数据保留 + 默认 0 + DDL 非幂等验证）；实测 `BookmarkDao.insert` 为 `ConflictAlgorithm.replace` upsert，覆盖同 id 行不会主键冲突。

- **影响范围**：无标题行书籍经 URL 导入时书架显示「download」；有标题行的书不受影响（书名取正文首行）。
- **修复方案（已验证）**：下载文件名取 `p.basename(uri.path)`——为空/`.`/`..` 时回落 `download.$ext`；文件系统保留字符（`\ / : * ? " < > |`）统一替换为 `_` 防止拼路径落盘失败。扩展名白名单已保证 basename 带合法扩展名。
- **核验方式**：新增 FT-URL-08（0 字节 `empty.txt` → 书名 `empty`）；原 FT-URL-01/07（有标题行、大写扩展名 + 查询串）不回归，全绿。

### DEF-14（P4）局域网上传 `name=..` 返回 500 —— ✅ 已修复

- **现象**（第五轮实证）：上传接口 `name=..` 时，`p.basename('..')` 返回 `..`（非空）越过校验，随后把临时文件 rename 到目录上报 OS 错误，返回 500（应为 400）。
- **复现步骤**：`POST /upload?name=..`（带正确 token）→ 500。
- **代码位置**：`lib/services/import/lan_transfer_server.dart:130` 的 safeName 校验。
- **影响范围**：无路径穿越、无数据损坏（写入被 OS 拒绝），仅状态码不规范；畸形客户端调用时才触发。
- **修复方案（已验证）**：`safeName` 为 `.` / `..` / 空时直接 `Response.badRequest`。
- **核验方式**：新增用例断言 `name=..` / `name=.` 均返回 400 且 inbox 零落盘；原路径穿越与消毒用例不回归，全绿。

### 第五轮 P4 观察项（非缺陷，记录在案）

- **URL 重定向短链被扩展名白名单拒绝**：原始 URL 无扩展名（如短链服务）时，下载前的 `p.extension(uri.path)` 检查即拒绝，即使重定向目标合法（实证：302 到 .txt 的链接报「只支持 txt / md / docx 文件」）。属设计取舍（按 URL 白名单更安全），若产品要支持短链需改为「下载后按内容/响应头判定」。
- **空白文件导入为 1 章空书**：纯空白 txt / 无段落 docx 可导入，得到 1 个空章节的书（不崩溃、不留异常数据）。UX 层面可考虑拒绝或提示。
