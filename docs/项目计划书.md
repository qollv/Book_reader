# 小说阅读器（novel_reader）项目计划书

> 版本：v0.1.0 ｜ 日期：2026-10-13 ｜ 状态：核心链路已实现，待联调验证

## 1. 项目概述

一款跨平台手机小说阅读软件。核心卖点：

- **本地导入 + 智能排版**：支持 txt / md / docx，自动完成段落重排、章节识别、首行缩进、分页优化，无需用户手动整理；
- **远程导入**：URL 直链下载、局域网互传（扫码配对）、云端进度同步三通道；
- **完整阅读体验**：书架管理、阅读进度自动记忆、书签、划词笔记、夜间模式、字体/字号/行距/页边距自由调整。

## 2. 技术选型

| 维度 | 选型 | 理由 |
| --- | --- | --- |
| 客户端框架 | Flutter 3.x（Dart） | 单代码库覆盖 Android/iOS，图文排版能力强，性能满足 60fps 翻页 |
| 状态管理 | Provider（ChangeNotifier） | 轻量、与 Flutter 官方生态一致，本项目状态面小，无需 Riverpod/Bloc 的额外概念 |
| 本地数据库 | sqflite | 移动端成熟的关系型存储，进度/书签/笔记结构清晰，SQL 便于后续同步合并 |
| 正文存储 | content.jsonl（一段一行 JSON） | 章节只存区间偏移，按需加载，避免把整本书读进内存 |
| 网络 | dio | 下载进度回调、拦截器、错误处理完善 |
| docx 解析 | archive + xml | docx 本质是 zip + XML，无需引入重量级 Office 库 |
| 局域网服务 | shelf + shelf_router | Dart 原生 HTTP 服务端，零 native 依赖 |
| 二维码 | qr_flutter | 局域网配对展示 |

## 5. 数据模型

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| books | id, title, author, format, content_path, chapter_count, total_chars | 书籍元信息；正文不在库内 |
| chapters | book_id, chapter_index, title, paragraph_start, paragraph_end | 章节 = content.jsonl 的段落区间 |
| progress | book_id, chapter_index, paragraph_index, line_index, percent, updated_at | 每本书一行；**锚点式进度**，重排版后不错位 |
| bookmarks | id, book_id, 锚点三件套, excerpt, comment, created_at | 书签可带短评 |
| notes | id, book_id, 锚点三件套, selected_text, content, updated_at | 划词笔记 |
| settings | id=0, payload | ReaderSettings 的 JSON 单行 |

**进度锚点设计**：不用页码存进度，而用「章 + 段 + 行」。字号/行距/屏幕变化会改变分页结果，页码随之漂移；锚点指向正文位置，重排版后用 `findPageForAnchor` 重新定位，阅读位置不丢。

## 6. 核心功能模块设计

### 6.1 导入与解析管线

```
文件 → BookParser（按扩展名分发）
     → txt: 章节正则 + TextNormalizer 续行合并
     → md : 标题/引用/列表/代码块结构化 + 行内语法剥离
     → docx: zip 解压 → w:p 段落 + w:pStyle 标题识别
     → ParsedBook（章节 + 段落块）
     → 写 content.jsonl + books/chapters/progress 三表入库
```

解析失败即抛异常回滚，不留半成品数据。扩展名白名单 + 100MB 大小上限防滥用。

### 6.2 智能分页引擎（核心）

`Paginator.paginate(blocks, config) → List<ReaderPage>`，输入规范化段落块与排版参数，输出页列表：

1. **测行**：`TextPainter.layout(maxWidth)` + `computeLineMetrics()` 逐段测行，行高即渲染行高——分页结果与视觉严格一致；
2. **首行缩进安全**：所有行按「内容宽 − 2 字缩进」测量，缩进渲染后任何一行都不会溢出；
3. **标题 keep-with-next**：剩余空间放不下「标题 + 2 行正文」时先把标题放到下一页，杜绝标题孤悬页尾；
4. **孤行控制**：段落拆页后任一侧只剩 1 行时整段挪页；段落比一页还长时按每页最大行数硬切；
5. **锚点携带**：每行带（章内段落下标, 段内行下标），支撑进度恢复、书签、笔记跳转。

分页结果按 `bookId|章节|排版参数指纹` 缓存，滑过的章节二次进入零计算；改字号/行距只重排当前章，并保持锚点。

### 6.3 阅读器渲染

- 每页一个 `PageView` 页项，内容按行渲染：首行缩进 2 字、标题加粗居中、引用左侧竖线、代码等宽底纹；
- 长按任意行 → 写笔记对话框；点按屏幕中央 → 呼出上下菜单；
- 底部滑块拖进度、目录跳章、夜间/日间一键切换；
- 屏幕尺寸或外观参数变化 → `postFrameCallback` 中重排版并跳回原锚点页。

### 6.4 远程导入与同步

**三种远程通道**：

| 通道 | 机制 | 用途 |
| --- | --- | --- |
| URL 导入 | dio 直链下载（仅 http/https、白名单扩展名、100MB 上限） | 网盘直链、自建书库 |
| 局域网 | 本机 shelf 服务 + 扫码配对（IP/端口/6 位令牌） | 与电脑/平板互传，不走外网 |
| 云端同步 | `SyncTransport` 接口，内置 LAN 与 HTTP 两种实现 | 多设备进度/书签/笔记合并 |

**同步协议**：`SyncPayload { device_id, progress[], bookmarks[], notes[] }`，JSON over HTTP；合并策略 **last-write-wins**（逐条比 `updated_at`）。删除操作不传播（防误删他端数据），记为已知限制。

局域网服务端点：

- `GET /info` 设备自报家门
- `GET /books` / `GET /books/<name>` 拉取书库文件（需 `X-Token`）
- `POST /upload?name=` 推送文件到 inbox（需 `X-Token`，文件名做 basename 消毒防路径穿越）
- `GET/POST /sync` 同步数据存取（需 `X-Token`）

### 6.5 夜间模式与字体调整

- 5 套配色（纸白/羊皮/护眼/夜间/深蓝），夜间配色强制深色主题，避免「系统日间 + 夜间底色」违和组合；
- 字体（系统/宋体/楷体）、字号 80%–160%、行距 1.4–2.4、页边距三档、翻页方式（左右滑动/上下滚动/淡入）；
- 所有设置即时持久化到 settings 表，改任一参数触发当前章重排。

## 7. 性能与适配策略

- **内存**：正文一段一行按需加载章节区间，不整书载入；分页结果 LRU 缓存（上限 12 章，`LinkedHashMap` 实现，排版参数变化/删书自然淘汰）；
- **卡顿**：分页是 O(段落数) 的同步计算，只在切章/改设置时发生，翻页本身零计算；进度写库 300ms 防抖，拖滑块不逐帧落库；
- **适配**：分页参数全部来自 `MediaQuery` 实际屏幕尺寸 + 用户设置，平板/折叠屏/横竖屏自动重排；
- **包体**：无 native 插件强制依赖（shelf/qr/fast_gbk 均为纯 Dart 实现）。

## 8. 安全与隐私

- 局域网服务所有数据接口校验 8 位令牌，同网段其他设备无法读写；
- 上传文件名 basename 消毒，阻断 `../` 路径穿越（三种编码均有回归测试锁定）；
- 请求体 100MB 上限（先查 content-length 再按流累计），超限 413；
- 写入采用临时文件 + rename 原子落盘，中断不留半个文件；
- URL 导入限制 scheme 与扩展名白名单，下载前预检大小、30s 超时；
- 全部数据本地存储，无遥测；云端同步地址与令牌由用户自填（首次同步弹配置框），程序不内置任何默认端点。

## 10. 已知限制

- docx 仅提取正文文本（含 Word 标题样式识别），图片/复杂表格忽略；
- 淡入翻页暂复用滑动动画（Flutter PageView 定制转场成本高，M6 后评估）；
- 书签删除按锚点匹配，暂不支持同页多书签；
- 云端同步需用户自备服务端，仓库内不含服务端实现；删除操作不在设备间传播（防误删）；
- 局域网传输只有"本机起服务、对端连接"方向，App 内暂无扫码客户端；
- Web 平台仅验证编译，运行时未支持（sqflite/dart:io 限制）。
