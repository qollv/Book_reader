# 小说阅读器（novel_reader）项目计划书

> 版本：v0.2.0 ｜ 状态：本地链路 + 在线数据源均已实现，待真机联调
> v0.2 变更：新增**在线数据源**子系统（声明式 JSON 源 + 规则引擎 + 探索/搜索/源管理），
> 阅读链路对「本地导入」与「在线导入」完全一致。

## 1. 项目概述

一款跨平台手机小说阅读软件。两条并行的能力线：

**A. 本地导入与智能排版**

- **本地导入 + 智能排版**：支持 txt / md / docx，自动完成段落重排、章节识别、首行缩进、分页优化，无需用户手动整理；
- **完整阅读体验**：书架管理、阅读进度自动记忆、书签、划词笔记、夜间模式、字体/字号/行距/页边距自由调整；
- **远程导入**：URL 直链下载、局域网互传（扫码配对）。

**B. 在线数据源（v0.2 新增）**

- **声明式数据源**：一个源 = 一份 JSON 声明（URL 模板 + CSS 选择器 + 字段算子），
  不需要编译、不需要安装可执行插件；
- **探索与搜索**：按源声明的探索页生成 tab，支持单选项/开关/滑块过滤器；搜索为事件流，允许部分成功；
- **导入即离线**：整本抓取后落成与本地导入同构的 content.jsonl，之后完全离线可读；
- **缓存与容错**：章节级本地缓存 + 本地优先双发射（先缓存后网络）、HTTP 缓存与请求合并、
  退出后仍可读已缓存的章节。


## 2. 技术选型

| 维度 | 选型 | 理由 |
| --- | --- | --- |
| 客户端框架 | Flutter 3.x（Dart） | 单代码库覆盖 Android/iOS，图文排版能力强，性能满足 60fps 翻页 |
| 状态管理 | Provider（ChangeNotifier） | 轻量、与 Flutter 官方生态一致，本项目状态面小，无需 Riverpod/Bloc 的额外概念 |
| 本地数据库 | sqflite | 移动端成熟的关系型存储，进度/书签/笔记结构清晰，SQL 便于后续同步合并 |
| 正文存储 | content.jsonl（一段一行 JSON） | 章节只存区间偏移，按需加载，避免把整本书读进内存 |
| 网络 | dio | 下载进度回调、拦截器、错误处理完善 |
| 在线源传输 | dart:io HttpClient（`HttpFetcher` 抽象） | 阅读器只需要 GET；抽象出传输层后，规则引擎/仓库/界面全部可用内存桩离线测试 |
| HTML 解析 | html + csslib | 纯 Dart 的 CSS 选择器实现，零 native 依赖 |
| 文本编码 | charset | 纯 Dart 的 GBK/GB18030 等编码；中文站点普遍在响应头写错 charset |
| docx 解析 | archive + xml | docx 本质是 zip + XML，无需引入重量级 Office 库 |
| 局域网服务 | shelf + shelf_router | Dart 原生 HTTP 服务端，零 native 依赖 |
| 二维码 | qr_flutter | 局域网配对展示 |

## 5. 数据模型

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| books | id, title, author, format, content_path, chapter_count, total_chars, **source_id, source_book_id, cover_url** | 书籍元信息；正文不在库内 |
| chapters | book_id, chapter_index, title, paragraph_start, paragraph_end | 章节 = content.jsonl 的段落区间 |
| progress | book_id, chapter_index, paragraph_index, line_index, percent, updated_at | 每本书一行；**锚点式进度**，重排版后不错位 |
| bookmarks | id, book_id, 锚点三件套, excerpt, comment, created_at | 书签可带短评 |
| notes | id, book_id, 锚点三件套, selected_text, content, updated_at | 划词笔记 |
| settings | id=0, payload | ReaderSettings 的 JSON 单行 |
| **sources** | id, name, manifest, enabled, installed_at, updated_at, last_error, origin | 在线数据源声明与其状态 |
| **chapter_cache** | (source_id, book_id, chapter_id) 主键, title, content, prev_id, next_id, fetched_at | 在线章节正文缓存，承载离线可读 |

**版本演进**：schema 版本 2，`data/schema.dart` 单独持有建表与迁移脚本，
测试可以对同一份脚本跑「新装」与「v1 升级」两条路径——
迁移脚本是最容易写错又最不容易被测到的代码，所以把它挪到能被测的地方。

**进度锚点设计**：不用页码存进度，而用「章 + 段 + 行」。字号/行距/屏幕变化会改变分页结果，页码随之漂移；锚点指向正文位置，重排版后用 `findPageForAnchor` 重新定位，阅读位置不丢。

**在线书与本地书同构**：在线导入同样写成 content.jsonl + chapters 区间，
`format = 'online'`、`source_id` / `source_book_id` 只用于回源与去重。
于是阅读器、分页、进度、书签、笔记全部不需要为在线书写分支。

## 6. 核心功能模块设计

### 6.1 导入与解析管线

```
文件 → BookParser（按扩展名分发）
     → txt: 章节正则 + TextNormalizer 续行合并
     → md : 标题/引用/列表/代码块结构化 + 行内语法剥离
     → docx: zip 解压 → w:p 段落 + w:pStyle 标题识别
     → ParsedBook（章节 + 段落块）
     → 写 content.jsonl + books/chapters/progress 三表入库
```

解析失败即抛异常回滚，不留半成品数据。扩展名白名单 + 100MB 大小上限防滥用。

### 6.2 智能分页引擎（核心）

`Paginator.paginate(blocks, config) → List<ReaderPage>`，输入规范化段落块与排版参数，输出页列表：

1. **测行**：`TextPainter.layout(maxWidth)` + `computeLineMetrics()` 逐段测行，行高即渲染行高——分页结果与视觉严格一致；
2. **首行缩进安全**：所有行按「内容宽 − 2 字缩进」测量，缩进渲染后任何一行都不会溢出；
3. **标题 keep-with-next**：剩余空间放不下「标题 + 2 行正文」时先把标题放到下一页，杜绝标题孤悬页尾；
4. **孤行控制**：段落拆页后任一侧只剩 1 行时整段挪页；段落比一页还长时按每页最大行数硬切；
5. **锚点携带**：每行带（章内段落下标, 段内行下标），支撑进度恢复、书签、笔记跳转。

分页结果按 `bookId|章节|排版参数指纹` 缓存，滑过的章节二次进入零计算；改字号/行距只重排当前章，并保持锚点。

### 6.3 阅读器渲染

- 每页一个 `PageView` 页项，内容按行渲染：首行缩进 2 字、标题加粗居中、引用左侧竖线、代码等宽底纹；
- 长按任意行 → 写笔记对话框；点按屏幕中央 → 呼出上下菜单；
- 底部滑块拖进度、目录跳章、夜间/日间一键切换；
- 屏幕尺寸或外观参数变化 → `postFrameCallback` 中重排版并跳回原锚点页。

### 6.4 远程导入与同步

**三种远程通道**：

| 通道 | 机制 | 用途 |
| --- | --- | --- |
| URL 导入 | dio 直链下载（仅 http/https、白名单扩展名、100MB 上限） | 网盘直链、自建书库 |
| 局域网 | 本机 shelf 服务 + 扫码配对（IP/端口/6 位令牌） | 与电脑/平板互传，不走外网 |
| 云端同步 | `SyncTransport` 接口，内置 LAN 与 HTTP 两种实现 | 多设备进度/书签/笔记合并 |

**同步协议**：`SyncPayload { device_id, progress[], bookmarks[], notes[] }`，JSON over HTTP；合并策略 **last-write-wins**（逐条比 `updated_at`）。删除操作不传播（防误删他端数据），记为已知限制。

局域网服务端点：

- `GET /info` 设备自报家门
- `GET /books` / `GET /books/<name>` 拉取书库文件（需 `X-Token`）
- `POST /upload?name=` 推送文件到 inbox（需 `X-Token`，文件名做 basename 消毒防路径穿越）
- `GET/POST /sync` 同步数据存取（需 `X-Token`）

### 6.5 夜间模式与字体调整

- 5 套配色（纸白/羊皮/护眼/夜间/深蓝），夜间配色强制深色主题，避免「系统日间 + 夜间底色」违和组合；
- 字体（系统/宋体/楷体）、字号 80%–160%、行距 1.4–2.4、页边距三档、翻页方式（左右滑动/上下滚动/淡入）；
- 所有设置即时持久化到 settings 表，改任一参数触发当前章重排。

### 6.6 在线数据源（v0.2 新增）

**一句话**：一个数据源 = 一份 JSON 声明。不用编译、不用装 APK，
「URL 模板 + CSS 选择器 + 字段算子」就能把一个站点接进来。

**分层**

```
界面（探索页 / 搜索页 / 源管理）
  ↓
状态（SourceController 管安装启停、ExploreController 管列表与搜索）
  ↓
仓库（OnlineBookRepository：本地优先双发射、写穿缓存、整本导入书架）
  ↓
引擎（JsonRuleEngine：解释声明）  ←→  注册表（SourceRegistry：兼容门控、启停、错误留痕）
  ↓
传输（CachedHttp：编码/缓存/合并/重试）→ HttpFetcher（dart:io，可换成内存桩）
```

**声明长什么样**（节选自 `assets/sources/sample_source.json`）

```json
{
  "id": "sample.demo", "baseUrl": "http://127.0.0.1:8765", "charset": "utf-8",
  "capabilities": ["search", "explore", "bookInfo", "volumes", "chapter"],
  "bookInfo": { "path": "/book/{id}", "fields": {
      "title": "#info h1",
      "author": "#info .author|replace:作者：,",
      "cover": "#info img.cover@src",
      "tags": ".tag" } },
  "volumes": { "path": "/book/{id}", "volumes": ".volume", "volumeTitle": ".volume-title",
      "chapters": "li a", "chapterFields": { "id": "@href|regex:/read/(\\d+)" } },
  "chapter": { "path": "/read/{chapterId}", "content": "#content p",
      "next": "#next@href|regex:/read/(\\d+)" }
}
```

字段规格语法：`选择器@属性|算子|算子`；算子支持 `trim`、`absUrl`、`number`、
`regex:模式`、`replace:旧,新`。URL 模板支持 `{id}` `{chapterId}` `{q}` `{page}` `{extra}`。

**关键设计决策**

1. **传输层抽象**：`HttpFetcher` 把「怎么发请求」与「怎么用响应」分开，
   于是规则引擎、注册表、仓库、界面全部能用内存桩离线测试（见测试规模一节）。
2. **编码显式化**：先取 bytes，再按**源声明的编码**解码。中文站点普遍在响应头里
   写错 charset（声明 iso-8859-1、正文是 GBK），依赖响应头必然乱码。
3. **本地优先双发射**：`chapterStream` 先吐缓存，再吐网络结果并写穿缓存；
   网络失败而本地有缓存时静默降级为离线读，只把故障记到源的 `last_error`——
   用户正在看的章节不该因为断网变成错误页。
4. **刷新必须穿透两层**：`refresh: true` 同时绕过数据库缓存与 HTTP 缓存。
   只跳一层会得到「刷新了但还是旧内容」的假刷新。
5. **先校验后落库**：安装一份声明时任何结构性错误都直接拒绝，且完全不动库里已有那行，
   失败的更新不会把用户已经能用的源弄坏。另有**版本防降级**与**分组式 API 兼容**
   （跨组完全不兼容、组内要求 `源 ≤ 宿主`）。
6. **坏数据降级而非崩溃**：解析组件/字段时缺字段、选择器失效一律产出可读错误；
   一个坏源不会拖垮其它源（`SourceManifest` 校验期拦截 + 加载期标 `error` 状态）。
7. **导入即同构**：整本抓完才落盘（避免留下半本书），写出的 content.jsonl 与本地导入
   完全一致，重复导入复用同一个本地 bookId，因此阅读进度与书签不会丢。

**测试策略**

- 静态 HTML fixture + `FakeHttpFetcher`：规则引擎、缓存、重试、编码全部离线测；
  真实站点的选择器随时会变，测它等于测别人的网站。
- `FixtureSite`（`tool/fixture_site.dart`）：可嵌入测试进程的本地站点，
  用来验证**真实 dart:io 传输**这一条链路（桩测不出请求头怎么发、字节怎么落）。
- sqflite ffi + 生产同一份 schema 脚本：DAO、迁移、注册表、在线仓库都在主机上跑单测。


## 7. 性能与适配策略

- **内存**：正文一段一行按需加载章节区间，不整书载入；分页结果 LRU 式缓存；
- **在线请求**：HTTP 层做请求合并（同 URL 并发只发一次）+ TTL 缓存 + 单源并发上限；
  分页加载在触底前 400px 预取；过滤器滑块**松手才发请求**（拖动过程只改本地值）；
- **卡顿**：分页是 O(段落数) 的同步计算，只在切章/改设置时发生，翻页本身零计算；
- **适配**：分页参数全部来自 `MediaQuery` 实际屏幕尺寸 + 用户设置，平板/折叠屏/横竖屏自动重排；
- **包体**：无 native 插件强制依赖（shelf/qr 均为纯 Dart 实现）。

## 8. 安全与隐私

- 局域网服务所有数据接口校验令牌，同网段其他设备无法读写；
- 上传文件名 basename 消毒，阻断 `../` 路径穿越；
- URL 导入限制 scheme 与扩展名白名单；
- **在线源声明在安装期做结构校验**：必填字段、能力与规则必须自洽、
  编码必须是已知编码、API 版本必须落在同一兼容组内，任一不满足即拒绝安装；
- 源的失败原因持久化到 `sources.last_error`，管理页直接展示，不吞错误；
- 全部数据本地存储，无遥测；云端同步地址与令牌由用户自填，程序不内置任何默认端点；
- 内置示例源只指向 `127.0.0.1`，不携带任何第三方站点凭据或默认端点。

## 10. 已知限制

- docx 只提取正文文本：图片忽略，表格内文字会并入正文而不还原成表格；
- 淡入翻页暂复用滑动动画（Flutter PageView 定制转场成本高，M6 后评估）；
- 书签删除按锚点匹配，暂不支持同页多书签；
- 云端同步需用户自备服务端，仓库内不含服务端实现；
- **在线源**：只支持 HTML 页面型站点（不解析 JSON API 与 JS 渲染站点）；
  正文目前只取纯文本段落，章节内的插图不入库；
  源的「下一页」暂以「返回空列表」判末页，未使用声明里的 `paging.next`；
  未做源商店（远程安装与更新检查），安装方式是内置示例 / 粘贴 JSON / 本地文件。
- 分页测量宽度统一按「正文宽度 − 首行缩进 − 1px」计算：保证分页器只会
  **高估**高度。代价是长段落偶尔会提前一页分页，换来的是「不会溢出」；
- 段落内的空行不占页面高度（段间距已经负责分隔），所以带空行的原文会紧凑一点。

## 11. 运行方式

```bash
cd Book_reader

```

## 12. 缺陷修复记录（v0.2.1）

修掉的都是「用户一定会撞到、且后果严重」的问题。每条都有 assert 型回归测试
（位置在 `test/regression/`），不再依赖那批只打印不断言的 `zz_*` 诊断脚本。

### 12.1 docx 导入出空书 —— 致命

**症状**：一份正常的 docx（标题样式 + 正文）导入进来是**一本空书**，正文一个字都没有。

**根因**：`docx_parser.dart` 用 `element.findElements('w:t')` 取文本，而
`findElements` 只找**直接子节点**；docx 的结构是 `<w:p><w:r><w:t>`，
`w:t` 隔了两层，永远匹配不到 → 每段文本都是空串 → 被空判断全部丢弃。
`w:pStyle`（在 `<w:p><w:pPr>` 里）同理，标题识别也从未生效。
另外用 `String.fromCharCodes()` 解 UTF-8 XML 字节，中文会变乱码。

**修复**：改走 `XmlNode.descendants` 取后代；命名空间 + 本地名匹配
（不再依赖 `w:` 前缀这种惯例）；XML 按 BOM/UTF-8 解码；标题识别同时支持
`w:pStyle` 与 `w:outlineLvl`；`w:tab` / `w:br` 参与文本。
**测试**：`test/regression/docx_parser_test.dart`（11 例）。

### 12.2 GBK 编码的 txt 导入直接抛异常 —— 致命

**症状**：中文 txt 大量是 GBK/ANSI 编码，导入报
`FileSystemException: Failed to decode data using encoding 'utf-8'`——
一个和「编码」毫无关系、用户也无从处理的错误。误选 pdf 是同一个报错。

**根因**：`File(path).readAsString(encoding: utf8)` 写死 UTF-8，没有 BOM 探测、
没有回退、没有格式校验；未知扩展名还会「按 txt 兜底」，等于强行解析任何文件。

**修复**：新增 `core/text/byte_text_decoder.dart`：BOM 优先 → **严格 UTF-8** →
GBK/GB18030 回退（顺序很重要：几乎任何字节序列在 GBK 下都能解出「像字」的东西，
先猜 GBK 会把正常 UTF-8 中文解成乱码）；NUL 占比判二进制；空文件单独报错。
新增 `core/parsers/book_file_guard.dart`：扩展名白名单（不再兜底）、存在性、
大小上限 100 MB、非空。两类异常都带可直接展示的中文信息，并在
`BookshelfController._friendlyError` 里显式识别。
**测试**：`test/regression/txt_encoding_test.dart`（16 例）。

### 12.3 content.jsonl 一行损坏就让整章打不开

**根因**：`ParagraphBlock.fromJson` 用 `json['level'] as int` 硬转，
缺字段即抛；而 jsonl 是**逐行**读的，一行坏掉整章失败。
`Book` / `Chapter` / `ReadingProgress` 的 `fromRow` 同样硬转
（`percent` 是整数时 `as double` 也会抛）。

**修复**：全部改为容错取值 + 合理退化（缺字段退化成普通段落/空串/0，
`level` 钳到 1..6，`percent` 钳到 0..1）；`loadChapterBlocks` 逐行 try/catch，
坏行只跳过并计数到 `lastSkippedLines`；章节缓存的 `_decode` 坏了当「缓存不可用」，
转去走网络而不是报错。**测试**：`test/regression/model_robustness_test.dart`（15 例）。

### 12.4 设置数据脏了就启动崩溃

**根因**：`ReaderSettings.decode` 直接 `jsonDecode(...) as Map` + `as int`：
`margin_index: 7` → `RangeError`、缺字段 → `type 'Null' is not a subtype of type 'int'`、
非 JSON → `FormatException`。设置读的是启动路径上的表，脏数据一定存在过。

**修复**：`decode` 改为**永不抛异常**——非 JSON/非对象/缺字段/类型不符
一律退化成默认值，越界值钳到合法区间；`horizontalMargin` 等 getter 也做了
防御性钳位。`paletteCount` 与真实配色数量的一致性由测试钉住，避免两边漂移。
**测试**：`test/regression/settings_robustness_test.dart`（15 例）。

### 12.5 markdown 行内语法把 `$1` 塞进正文

**症状**：`**粗体**` 在正文里变成字面量 `$1`；`*斜体*` 变成 `$1$2`。

**根因**：`String.replaceAll` 的替换串是**字面量**，不支持 `$1` 反向引用
（只有 `replaceAllMapped` 支持）。原实现整段用 `replaceAll(re, r'$1')`。
顺带发现下划线斜体的正则会把 `snake_case_name` 当成斜体吃掉中间一段。

**修复**：全部改走 `replaceAllMapped` + 显式取组；下划线斜体只在词边界
（`\b`）生效，`snake_case` 原样保留。另外 md 的书名提取会先剥掉 `#`
（原先书名会带井号，且和正文去重比对不上、正文里重复出现标题）。
**测试**：`test/regression/markdown_inline_test.dart`（9 例）+ 12.2 的 md 用例。

### 12.6 代码块渲染溢出页面

**症状**：小屏上代码块画出页面外，实测渲染 400.4px / 可用 280px。

**根因**：分页器和渲染器在「一行占多高」上不一致：
渲染器给不同段落类型加了额外内外边距（代码块每行 **1.4 倍字号**：上下
各 0.2 字号外边距 + 0.5 字号内边距），分页器完全没算；
代码块渲染还换成了等宽字体，而分页仍按「比例字体 + 0.9 倍字号」测量——
字体度量不同，量出来放得下、渲染出来放不下。

**修复**：把「字体缩放 / 字体族 / 每行额外垂直占位 / 段间距」四件事收到
`core/pagination/line_box.dart`，分页与渲染都从这里取，改一处两边同时生效；
渲染端补上段间距（原先分页算了、渲染没画）。
**测试**：`test/regression/reader_page_overflow_test.dart` —— 把分页结果
**真的渲染出来量像素**，断言内容高度不超过可用高度（9 例，覆盖
320/400/640 三种页高、纯代码块、放大字号）。

### 12.7 顺带查出的两个更严重的问题（同一批测试暴露）

- **正文丢字**：`getLineBoundary` 在 offset 正好落在 `\n` 上时会「只返回换行符」，
  形成伪行。伪行有两个后果：多占一整行高度（`"\n"` 渲染出来是 64px），
  以及循环次数受真实可视行数限制、**把真正的最后一行挤出循环**——
  也就是多行段落会丢字。修法是跳过纯空白伪行并保证指针前进。
- **分页测量必须偏保守**：字号放到 26 时，10 个汉字的文本宽度正好等于可用
  宽度，分页判定 1 行、渲染却换行成 2 行（渲染端缩进 `baseSize * 2` 参与
  浮点运算，宽度会差零点几像素）。现在统一减掉 1px 安全余量，把「恰好等于」
  的边界情况推向安全一侧：**宁可多分一页，不能溢出**。

## 13. 尚未验证的部分

必须说清楚，避免过度自信：

- **应用从未在真机上跑过**：本机 `flutter devices` 只有 Windows 与 Edge，
  没有 Android 设备也没有模拟器。APK 能构建、能通过 `aapt2` 静态校验，但
  一帧都没在设备上渲染过，也没有人手动点过一遍完整流程；
- **在线源只跑过我写的 fixture 站点**（`127.0.0.1`），没有对接任何真实小说站。
  真实站点的选择器、反爬（Cookie/UA 校验/限速）、JS 渲染页面都未经验证；
- 界面层只有 widget 测试断言「渲染出了某段文字」，没有视觉回归与真机交互验证；
- `test/zz_*.dart` 是早期分析留下的一批**只打印不断言**的复现脚本，
  跑起来永远「通过」。本次修复对应的断言已经落在 `test/regression/`，
  这批评测脚本建议后续清理或改写成断言型测试。
